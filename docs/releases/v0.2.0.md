# v0.2.0 - Distributed Scalability with Redis

Following our vision of an enterprise-grade AI Runtime Framework, **v0.2.0** introduces a significant architectural leap: **Distributed Event Bus capability via Redis**.

## 🚀 Key Features

### The Adapter Pattern for Event Bus
The core `EventBus` has been refactored to support pluggable adapters. 
- By default, the framework uses an `InMemoryAdapter`, making it lightweight and zero-config for simple or single-node applications.
- You can now inject custom adapters to power the Event Bus with robust message brokers.

### The `RedisAdapter` (Included in Core)
We have bundled `RedisAdapter` (powered by `ioredis`) directly into the core framework. 
When configured, Agents running on separate Node.js processes—or entirely different servers—can seamlessly publish and subscribe to the same events. 

This enables you to build **multi-agent architectures** where AI agents are decoupled and distributed across microservices.

## 💻 Quick Start: Redis Adapter

```typescript
import { Runtime, RedisAdapter } from "@agent-runtime/core";

// Connect to your Redis instance
const redisAdapter = new RedisAdapter({ host: "127.0.0.1", port: 6379 });

const runtime = new Runtime({
  eventBusAdapter: redisAdapter
});

// Start your runtime! 
// Any `runtime.publish()` or `bus.subscribe()` now flows through Redis Pub/Sub.
await runtime.start();
```

See the full example in [`examples/redis-agent/index.ts`](../examples/redis-agent/index.ts).

## 🛠 Breaking Changes (Internal API)
- `Runtime.start()` is now asynchronous (`async / await`) because the adapter connection (e.g., to Redis) needs to be established. Make sure to await `runtime.start()`.
- `EventBus` constructor now requires an `EventBusAdapter`. (If you use `new Runtime()`, this is handled automatically for you).

## 🛤️ What's Next? (Roadmap to v0.3.0)
With Redis handling basic distributed Pub/Sub, the next step is robust, enterprise messaging. In **v0.3.0**, we will introduce the **RabbitMQ Adapter**, bringing support for dead-letter queues, message persistence, and delivery guarantees.
